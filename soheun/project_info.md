# Project Information

## Overview
- This repository implements methods for data-driven background modeling in double Higgs boson production (4b final state).
- The `soheun` directory contains a PyTorch Lightning–based implementation of the FvT (Four vs. Three) classifier.
- Core components include:
  - `soheun/fvt_classifier.py`: definition of the `FvTClassifier` LightningModule.
  - `soheun/fvt_encoder.py`: feature encoder for jet, dijet, and quadjet inputs.
  - `soheun/attention_classifier.py`: attention-based classification head.
  - `soheun/data_modules.py`: `FvTDataModule` for data loading.

## Key File: soheun/fvt_classifier.py
- Defines `FvTClassifier`, which encapsulates:
  - Model architecture: encoder + attention classifier.
  - Training, validation, and prediction logic with PyTorch Lightning.
  - Custom optimizer support (e.g., schedule-free Adam).
  - Data preloading (`preload_to_gpu`), logging, checkpointing, and callbacks.

## Performance Improvement Tasks
To accelerate training of `FvTClassifier`, consider the following tasks:

1. **Data Loading Optimization**
   - Enable `pin_memory=True` in `DataLoader` for faster host-to-device copies.
   - Set `persistent_workers=True` and tune `num_workers` to maximize I/O throughput.
   - Adjust `prefetch_factor` to prefetch batches in advance.

2. **GPU Data Preloading**
   - Enhance the `preload_to_gpu` mechanism to ensure dataset tensors persist on GPU across epochs.
   - Fall back gracefully when GPU memory is insufficient, with minimal CPU–GPU transfers.

3. **Mixed Precision Training**
   - Enable automatic mixed precision (AMP) by passing `precision=16` to the Lightning `Trainer`.
   - Reduce memory footprint and increase arithmetic throughput on supported hardware.

4. **Multi‑GPU & Distributed Training**
   - Configure the Lightning `Trainer` with `accelerator='gpu'`, `devices>1`, and `strategy='ddp'` or `ddp_spawn`.
   - Leverage multiple GPUs to parallelize both data loading and model computation.

5. **Model Compilation & JIT**
   - Apply `torch.compile()` (PyTorch 2.0+) to the `FvTClassifier` for graph-level optimizations.
   - Consider `torch.jit.trace` or `torch.jit.script` if compatibility allows.

6. **Profiling & Benchmarking**
   - Integrate `torch.profiler` or Lightning's `Profiler` callback to identify CPU/GPU hotspots.
   - Benchmark various batch sizes, data loading configurations, and precision settings.

7. **Batch Size Scheduling & Gradient Accumulation**
   - Exploit `batch_size_milestones` in `FvTDataModule` for adaptive batch sizing.
   - Add support for `accumulate_grad_batches` in the `Trainer` to simulate larger batch sizes without extra memory.

8. **Data & Computation Pipeline Fusion**
   - Fuse preprocessing steps (e.g., normalization, augmentation) with GPU kernels when possible.
   - Move lightweight transforms into the model's `forward` to reduce Python overhead.

9. **Caching & Memory Reuse**
   - Cache preprocessed inputs or intermediate representations to avoid redundant work.
   - Reuse memory buffers where possible to reduce allocation overhead.

10. **TorchScript & ONNX Export**
    - Experiment with exporting the model to TorchScript or ONNX for optimized runtimes.
